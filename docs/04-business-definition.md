# 業務定義書

文書番号: EVA-BR-001  
版: 0.2（草案）  
作成日: 2026-09-02  
更新: レッスン体験フォーム追加、EVENT を History 枠に変更  
対象: Eva.Oriental Dance Studio 公式サイト リプレース

## 1. 目的

和歌山市のベリーダンス・ヨガ・ピラティス教室「Eva.Oriental」の公式サイトを、Wix から自前の Next.js サイトへ移す。

サイトの役割は次の3つです。

1. 教室の世界観と活動を伝える
2. レッスン・イベント・スタジオの情報を届ける
3. 体験申込・レンタル問い合わせを受け、スプレッドシートに残す

伝える内容、デザインの土台、文言、アイコンは変えません。変えるのは、ページの使いやすさと運用のしやすさです。

| 役割 | 想定 |
| --- | --- |
| 事業主 / コンテンツオーナー | Eva.香陽（Eva.Oriental） |

## 3. 対象業務

### 3.1 情報発信

| 業務 | 内容 | 更新の目安 |
| --- | --- | --- |
| 教室紹介 | プロフィール、クラス説明、アクセス | 年に数回 |
| お知らせ | HOME「What's New」 | 月〜週 |
| イベント | 直近情報の追加、History 枠への過去移動 | 公演の前後 |
| スケジュール公開 | 月間表の画像 / PDF | 毎月 |
| ギャラリー | 公演写真の追加 | 公演後 |

### 3.2 レッスン体験（サイト内フォーム）

今回から、体験申込は自サイトのフォームで受け、指定スプレッドシートに追記する。現行の Google フォームは使わない。

置く場所:

- 専用ページ `/trial`
- HOME / ベリーダンス / ヨガ / スケジュールからの導線
- スケジュールページの「体験会予約はこちらから」は `/trial` に向ける

項目案（現行 Google フォームは開けなかったため、教室サイトとして必要最小限。確定前に確認）:

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| お名前 | 必須 | |
| Email | 必須 | 折り返し用 |
| 電話番号 | 必須 | LINE が使えない場合の連絡 |
| 希望クラス | 必須 | ベリーダンス / ヨガ&ピラティス / どちらでも |
| 希望日時 | 任意 | 自由記述（曜日・時間） |
| ダンス・ヨガ経験 | 任意 | 未経験 / 少しある / 経験あり |
| ご質問・メモ | 任意 | |

成功メッセージは問い合わせと同じく `詳細が無事送信されました！` を使う。出すのは、送信中アニメ → API成功後の完了アニメ → フェードアウトのあと。新規キャッチは足さない。

教室側の作業:

1. シートの新しい行を見る
2. メールまたは電話で日程を確定する
3. 必要なら LINE 案内を返す

reserva.be と LINE の表示は残してよいが、体験の主経路はサイト内フォームとする。

### 3.3 お問い合わせ（サイト内）

スタジオレンタルとアクセスの2ページに、同じ項目のフォームがあります。

受信項目:

- お名前（必須）
- Email（必須）
- 件名（任意）
- 本文（任意）
- 送信元ページ（システムで付与）
- 送信日時（システムで付与）

送信先は、体験と同じスプレッドシートの別タブ「お問い合わせ」です。

成功時の表示文言: `詳細が無事送信されました！`

### 3.4 スタジオレンタル

サイトは条件提示と問い合わせ受付までです。在庫管理、決済、鍵の受け渡しは対象外です。

提示する条件（現行文言）:

- 広さ `１０ｍ×７ｍ`
- `土足厳禁`
- 住所 `和歌山市本町四丁目 38 本町中央ビル 3F`
- 電話 `070 3261 0512`

## 4. 対象範囲

### 4.1 今やる範囲（第1期）

- 現行サイトの全公開ページを Next.js で再構築する
- 文言・ナビ名・アイコン・デザインベースを踏襲する
- お問い合わせとレッスン体験を、指定スプレッドシートの各タブへ記録する
- 過去イベントは EVENT ページの History 枠にまとめる（年別ページは作らない）
- Vercel に公開する
- 現行 Wix URL から新 URL へリダイレクトする
- 写真枠を用意し、後から差し替えられるようにする

### 4.2 今はやらない範囲

- 会員サイト、決済、在籍生向け予約の自前実装（reserva は残す）
- データベース（CMS 本格導入を含む）
- 体験フォーム以外の新規コピー追加（成功メッセージは現行流用）
- 多言語化
- 協会サイトの改修
- 写真の本撮影
- 文言のリライト、ブランディングの刷新
- LINE 公式や reserva の仕様変更

## 5. 業務フロー

### 5.1 レッスン体験

```
来訪者がクラスまたはスケジュールを読む
  → /trial で項目を入れて送信
  → サーバーがスプレッドシート「レッスン体験」に1行追加
  → 成功メッセージを表示
  → 教室側がシートを見て連絡する
```

### 5.2 お問い合わせ

```
来訪者がレンタルまたはアクセスを開く
  → 必須項目を入れて送信
  → サーバーがスプレッドシート「お問い合わせ」に1行追加
  → 画面に成功メッセージ
  → 教室側がシートを見てメールまたは電話で返信
```

### 5.3 お知らせ更新（運用）

第1期は開発者がコンテンツファイルを更新してデプロイします。教室側がブラウザから直編集する仕組みは第1期の必須ではありません。

更新対象の優先順位:

1. HOME お知らせ
2. 月間スケジュール画像
3. EVENT 直近
4. ギャラリー

## 6. 成功の定義

- 現行の全ページが新サイトで辿れる
- 主要文言が現行と同じに見える
- スマホでナビ・本文・フォームが使える
- 体験・問い合わせの送信が、指定シートの正しいタブに残る
- History 枠で 2015 年以降の過去イベントが読める
- Vercel 上で HTTPS 公開されている

## 7. 制約

- 文言・伝える内容・デザインベース・アイコンは変えない
- 写真は後工程。仮画像は現行に近い夜・舞台・オリエンタル寄りのテイストにする
- 個人情報はシートに残るため、シート権限は最小限にする
- Wix のブログ・予約機能は移植しない（外部サービスを継続）

## 8. リスク

| リスク | 影響 | 対応 |
| --- | --- | --- |
| 写真が揃わない | 空欄や仮画像のまま公開 | 枠を先に作り、差し替え手順を決める |
| 月間表が画像のまま | 検索・読み上げが弱い | 第1期は現行踏襲。テキスト化は別判断 |
| シート権限ミス | 問合せが見えない / 漏えい | 専用シート、サービスアカウント、編集者限定 |
| お知らせ更新が開発経由 | 反映が遅れる | 更新手順を短くする。必要なら第2期で簡易管理 |
| 現行の誤字を直す/残す | 意図しない文言変更 | 原則残す。直す場合は事前確認 |
